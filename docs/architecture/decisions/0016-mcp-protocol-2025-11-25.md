# 0016. /mcp also accepts protocol 2025-11-25, through the handshake but without sessions

**Status:** Accepted. Supersedes the protocol clause of [ADR-0014](0014-mcp-transport.md).
**Date:** 2026-10-09

## Context

ADR-0014 accepted only MCP protocol 2026-07-28. On 2026-10-09 that turned out to exclude two common clients:
- the TypeScript SDK 1.32.1, the library behind most Node-based agents;
- MCP Inspector 2.10.1, the standard debugging tool.

The newest revision either speaks is 2025-11-25, so `/mcp` answered both with `400 Unsupported protocol version`. An agent reported this through the feedback box (report `01a1210e-bb2d-70c4-ba8e-9de9e2debfff`), and it became [#21](https://github.com/ashuangiras/polaroid/issues/21).

## Decision

- **Two revisions.** `/mcp` accepts **2026-07-28** and **2025-11-25**. `server/discover` lists both, newest first.
- **Still sessionless.**
  - A 2025-11-25 client starts with the `initialize` handshake.
  - The handler stays in stateless mode with JSON responses, so no `Mcp-Session-Id` is issued and each POST still stands alone.
  - Tools, arguments, results, errors, resources, cache hints, limits, the loopback-host check and cross-origin protection are identical at both revisions.
- **Older revisions are never served.**
  - A request that names an older revision in `Mcp-Protocol-Version` is refused with `400`.
  - An `initialize` for an older revision is answered with 2025-11-25, as the MCP lifecycle requires. A client that cannot speak 2025-11-25 then disconnects. The Go SDK cannot refuse the handshake outright.
- **No planned removal.** 2025-11-25 stays until a later ADR removes it.

## Consequences

- TypeScript-SDK agents and MCP Inspector connect with only the URL, as Go SDK clients and VS Code Copilot chat already did.
- Two revisions must keep working. Tests cover the handshake revision, session-free responses and older revisions, alongside the 2026-07-28 tests.
- An older client is offered 2025-11-25 rather than refused outright. It is never served at its own revision.
